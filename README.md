# AI 应用项目作品集

> 从业务痛点出发、以可运行产物交付的 AI 应用工程项目集。

## 关于我

一名把"业务问题 → 技术选型 → 落地交付"作为方法论的 AI 应用工程实践者。

**为什么以业务背景切入 AI？** 零售、金融等行业的 AI 落地难点从来不在模型本身，而在能否把业务需求准确翻译成技术方案。我的实践路径是：先吃透业务（银行合规、简历写作、产业数据），再选择合适的技术栈（规则引擎 / RAG / Agent），最终交付能跑、能验证、能交付的完整系统。

## 项目一览

| 项目 | 一句话 | 技术栈 | 状态 |
|---|---|---|---|
| [resume-kit](/resume-kit) | AI 简历生成与审核 Agent：检索-生成-评估-重写闭环，单份定制简历分钟级交付 | Python · FAISS · Embedding · RAG · Agent · MCP 双协议 | 可运行，多岗位真实跑通 |
| [yunjian-compliance](/yunjian-compliance) | 云鉴·员工言论合规分析 Agent：8 类合规风险规则引擎 + OCR 图片审核 + 风险档案闭环 | Python · Flask · PaddleOCR · 自研规则引擎 | 可运行，银行课题落地 |

## 两个项目背后的同一套方法论

1. **先定义业务问题**：resume-kit 解决"简历量化难、匹配度低、信息失真"；云鉴解决"银行营销文案人工审核低效、关键词检索易遗漏"。
2. **再选择合适技术**：简历生成需要语义召回 → 用 RAG+FAISS；银行合规要可解释可审计 → 用规则引擎而非黑盒模型。
3. **最后交付闭环系统**：两个项目都有"输入 → 处理 → 输出 → 反馈进化"的完整闭环，且都带真实运行产物。

## 技术栈汇总

- **LLM 应用**：RAG、Agent 自主循环、MCP（SSE + Streamable HTTP）、多模型容灾
- **检索**：FAISS、sentence-transformers、TF-IDF
- **工程**：Python、Flask、标准库 HTTP 服务、规则引擎设计
- **多模态**：PaddleOCR（图片文字识别）
